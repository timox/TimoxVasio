# TimoxVasio 1.2.6

Cette version ajoute un suivi des performances audio et rend le routage plus lisible.

- **Performance** explique visuellement échantillon, fréquence, tampons ASIO et durée d'un bloc. Il affiche le CPU des applications routées et la durée du callback de chacune rapportée au temps disponible par bloc. Les mesures par étape restent facultatives.
- **Analysis** présente des courbes temporelles du callback physique, du CPU et du callback des applications, ainsi que les variations des compteurs underrun/overrun. La collecte s'effectue toutes les cinq secondes, hors du fil audio. Un export CSV permet l'analyse ultérieure.
- Les canaux configurés, ouverts et actuellement routés sont distingués. Les compteurs de transport sont communs aux canaux d'un même processus et d'un même sens ; ils ne localisent pas l'incident sur un canal ou un VST précis.
- **Routing** ouvre directement un patchbay inspiré de [PipeWireController](https://github.com/knightinfected/PipeWireController), désormais basé sur React Flow. Un processus réunit ses entrées et sorties dans un bloc. La carte se zoome avec les boutons +/− ou le pincement et se parcourt par glissement ; la molette fait défiler la page. Le bouton **Recenter graph** ramène immédiatement les blocs dans le champ. Les blocs se déplacent librement par leur en-tête et se renomment localement. Un clic droit sur un câble donne accès à ses propriétés dans une modale ; tirer son extrémité vers un autre port modifie la connexion en attente d'application, en conservant son gain et son état muet. La matrice reste ciblée sur une connexion choisie. Les types de ports et les états des câbles ont des signes distincts.
- Les blocs restent initialisés pendant leur déplacement et le graphe se recentre lorsque les filtres changent. Une recherche qui masque tous les ports affiche une explication et un bouton pour revenir aux connexions.
- Le menu gauche est réservé à la navigation et aux commandes globales. Les détails contextuels s’ouvrent exclusivement dans des modales depuis le menu contextuel, sans encart permanent autour du graphe. La matrice d'une connexion s'ouvre dans une fenêtre centrée. Les connexions d'un ancien nom d'exécutable ont un bloc distinct d'un profil de canaux ; l’action Configure process du menu contextuel permet de les déplacer vers un processus ouvert dans le brouillon, à vérifier avant **Apply configuration**.
- Un clic droit sur le fond ouvre l'ajout de connexion et le détail des canaux. Sur un processus, le menu permet d'ajouter un lien ou de choisir précisément celui à modifier ou supprimer. Sur un câble, les actions portent uniquement sur ce lien. Les ports n'affichent plus « (saved) » ; les connexions migrées sont consignées dans **Logs** après application.
- **ASIO setup** place la carte physique avant la liste des profils de capacité. Dans **Routing**, l’action Configure process du menu contextuel d’un processus présent lui attribue un profil (2 entrées et 2 sorties proposées). Le même panneau retire sa configuration et ses connexions après confirmation, sans fermer le processus Windows.
- Lorsqu'une autre carte physique est sélectionnée, **Routing** propose de transférer les connexions enregistrées vers les mêmes numéros de canaux. Le transfert conserve les sources, gains et états muets. Si un canal manque sur la nouvelle carte, une copie locale permet de rétablir l'ancienne carte et ses connexions.
- Control conserve les identifiants stables des applications dans le brouillon. Les connexions sauvegardées restent visibles même si leurs ports ne sont pas ouverts. Lorsqu'une autre application, notamment Mixette, ajoute des routes via l'API, **Apply configuration** fusionne les modifications indépendantes et signale un conflit sur une même connexion.
- **Discard pending edits** abandonne uniquement le brouillon. **Reset physical driver** rouvre la dernière configuration enregistrée sans effacer les connexions ; le son est brièvement interrompu.

Le spectre par fréquence d'un bloc n'est pas encore mesuré. Le moteur et le pilote portent tous deux la version 1.2.6. Les routes enregistrées sont conservées.

- **Expand all** déplie uniquement les ports reliés. Les ports inutilisés restent masqués ; chaque processus indique ses entrées et sorties utilisées / disponibles, même replié. Les ports libres se choisissent dans la modale d’ajout de connexion.

## Installation

Télécharger le [Setup 1.2.6](https://github.com/timox/TimoxVasio/releases/tag/v1.2.6) et le lancer. Il installe Control, le moteur et la DLL ASIO sans effacer la configuration enregistrée. Relancer ensuite les applications audio déjà ouvertes. Pour changer de carte physique, la sélectionner dans **ASIO setup**, puis utiliser **Switch driver and transfer connections** : l'interface ouvre la carte et migre les connexions en une action. Voir le [guide Windows](RELEASE_WINDOWS_1.2.6.md).
