## Assemblage

Le dépôt d’assemblage est `TimoxVSSC`. `artifacts.lock.json` doit rester la
source de vérité pour les binaires, révisions et SHA-256. Le portable contient
le GUI, le moteur alpha, le client PWAR et les schémas ; il n’installe pas et ne
réenregistre pas le driver 1.2.7.

Avant un build :

```powershell
git rev-parse --show-toplevel
git status --short --branch
npm run release-preflight
```

Les binaires attendus restent :

- `artifacts/backend/TimoxVirtualAsioEngine.exe`
- `artifacts/backend/PwarAsioClient.exe`

Un changement de source, de receipt, de schéma ou de hash doit arrêter le
packaging jusqu’à régénération et vérification des entrées correspondantes.

## Test portable au-dessus de 1.2.7

Le test local ne désinstalle rien. Le lanceur ferme uniquement les clients
TimoxVasio attachés, après confirmation, envoie `engine.stop`, vérifie l’absence
de clients et l’état `stopped`, libère l’ancien moteur, puis lance le portable :

```powershell
.\scripts\portable-overlay-handoff.ps1 `
  -StableEnginePath 'C:\Path\To\installed\TimoxVirtualAsioEngine.exe' `
  -PortableExePath '.\dist\TimoxVSSC-0.2.0-alpha.1-preview.exe' `
  -ConfirmHandoff
```

Utiliser `-NoLaunch` pour tester uniquement le handoff. Ne pas exécuter le
lanceur pendant une qualification audio non coordonnée. Le script est un outil
de test destructif volontaire ; `-WhatIf` existe dans l’ancien helper
`TimoxVasio/tools/stop-timox-test.ps1`.

## Règles de reprise

- Ne pas démarrer le moteur, la GUI, un client PWAR ou du matériel audio sans
  demande coordonnée explicite.
- Ne pas installer, enregistrer ou remplacer le driver stable 1.2.7.
- Ne pas créer de release alpha par accident.
- Ne pas remplacer les données `%APPDATA%/timox-vsounddealer` ni la protection
  single-instance.
- Toute nouvelle modification doit rester sur `main`, être vérifiée, puis
  être commitée et poussée avant de considérer la reprise terminée.
